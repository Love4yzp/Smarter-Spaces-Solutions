# 地库无线传感网络 - LoRa

随着城市发展和基础设施建设的深入，“地库”（泛指各类地下空间，包括但不限于地下车库、储藏室、设备层、人防工程、管廊等）的数量和规模日益增大。这些地下空间普遍存在**通信信号覆盖难**的问题，传统有线通信方案（如以太网、光纤）部署成本高、周期长、后期维护不便，尤其对于已建成的地库改造更是困难重重。Wi-Fi、蓝牙等无线技术在地下复杂结构中信号衰减严重，覆盖范围有限。

LoRa 免布线方案能够解决传统有线系统成本高昂、施工困难的痛点，为环境监测、安全保障、资产管理和节能控制等应用场景提供了经济高效的解决方案。

与此同时，Meshtastic 作为一个开源的 LoRa 网络方案，提供了一个**低成本、易部署、免布线、可自组网**的无线通信解决方案。

通过 Meshtastic 和 ReComputer R1000 系列的结合，能够接入传统的 RS485/Modbus 设备的同时，借助 NodeRED 进行低代码编程，极大地降低了开发成本。快速搭建和管理需要的应用。

## **技术选型**

在众多无线通信技术中，LoRa (Long Range) 技术因其**远距离、低功耗、强穿透性**的特点，在地下等复杂环境中展现出潜力。在本次方案中，这里对两种 LoRa 技术进行了对比。


| 协议层面       | Meshtastic 方案                                | LoRaWAN (对比参考)                            | 地库场景关注点                       |
| :--------- | :------------------------------------------- | :---------------------------------------- | :---------------------------- |
| **物理层**    | LoRa调制 (CSS), Sub-GHz ISM频段, 可配置SF/BW/CR     | LoRa调制 (CSS), Sub-GHz ISM频段, 可配置SF/BW/CR  | **高SF提升穿透和距离**，但降低速率；选择合适频段   |
| **网络拓扑**   | **Mesh (网状自组网)**                             | 星型 (Star of Stars)                        | **Mesh适应复杂结构，增强覆盖**           |
| **节点通信**   | 节点间多跳转发，动态路由                                 | 终端节点与网关通信                                 | Mesh提供路径冗余                    |
| **核心路由机制** | 基于Flooding和Store-and-Forward的分布式路由算法，节点维护邻居表 | 数据由网关转发至网络服务器(LNS)，LNS负责路由和设备管理           | Meshtastic路由简单高效，但大规模网络效率需关注  |
| **中心化程度**  | **去中心化**                                     | 中心化 (依赖LNS, Join Server)                  | 去中心化降低单点故障，简化小型网络部署           |
| **数据格式**   | Protocol Buffers (Protobuf) 为主               | 应用层数据格式由用户定义，LoRaWAN定义MAC层载荷              | Protobuf轻量高效                  |
| **加密机制**   | AES-256信道加密 (基于预共享密钥 PSK)                    | 端到端加密 (AppSKey), 网络层加密 (NwkSKey), AES-128 | 两者均提供加密，Meshtastic的PSK管理需注意安全 |
| **寻址方式**   | 基于节点ID进行寻址                                   | DevAddr (设备地址)                            | Meshtastic节点ID唯一标识            |
| **消息确认**   | 支持ACK机制，可配置重传                                | LoRaWAN支持Confirmed/Unconfirmed消息类型        | ACK提高可靠性，但增加开销和延迟             |
| **外部接口**   | BLE (App连接), Wi-Fi (TCP/IP, MQTT桥接), Serial  | 网关通过IP网络 (以太网,蜂窝) 连接LNS                   | Meshtastic提供多种灵活的数据导出方式       |


虽然 Meshtastic 在商业成熟度和标准化方面不如 LoRaWAN，但其Mesh特性和低成本优势使其成为解决地库通信难题的一个极具吸引力的差异化方案。

## 1应用场景

| 应用分类         | 具体场景举例                       | Meshtastic方案价值      |
| :----------- | :--------------------------- | :------------------ |

| **设备状态监控**   | 地下水泵、风机启停/故障状态，重要区域门磁开关状态    | 免布线监控，预防性维护         |
| **简单消息与应急**  | 巡检人员状态上报/短消息，应急信标            | 弥补手机信号盲区，提供基础应急通信手段 |
| **资产定位(辅助)** | 对移动设备或人员的大致区域定位 (基于RSSI或GPS) | 低成本实现粗略定位，辅助管理      |
| **能耗监测(低频)** | 对特定用电设备进行低频次的能耗数据采集          | 简化能耗数据获取途径          |
| **工业设备接入**       | 接入已有的的 Modbus 设备，而无需“智能升级”   | 拓展其的传输边界            |

### 传输协议定义

协议解析层负责定义和解析基于 Meshtastic 的 Modbus 通信协议。其核心功能是将 Modbus 命令封装为紧凑型 JSON 格式，通过 Meshtastic 网络进行传输，支持设备间的透传通信。

在未来可以采用 Protobuf 的方式进行传输。

- **设备标识**：通过 `i` 字段标识发送设备。
- **设备类型**：支持 Modbus RTU (`r`) 和 Modbus TCP (`t`) 两种设备类型。
- **协议版本管理**：通过 `v` 字段标识协议版本，当前版本为 `1`。
- **通道管理**：支持通过 `p` 字段标识 RS485 端口号或通信通道。
- **Modbus 命令封装**：支持以下 Modbus 功能码：
  - 读操作：`1` (读线圈)、`2` (读离散输入)、`3` (读保持寄存器)、`4` (读输入寄存器)
  - 写操作：`5` (写单个线圈)、`6` (写单个寄存器)、`15` (写多个线圈)、`16` (写多个寄存器)
- **数据封装**：支持通过 `d` 字段传输写操作所需的数据。
- **会话管理**：可选支持 `ss` 字段，用于请求与响应的关联。

#### 请求报文格式

```json
{
  "i": "string",    // 发送设备的 ShortName
  "t": "string",    // 设备类型 ("r" 或 "t")
  "v": "string",    // 协议版本号
  "p": "string",    // 通道号或端口号
  "c": {            // Modbus 命令对象
    "a": int,       // 从站地址 (1-247)
    "f": int,       // 功能码 (1, 2, 3, 4, 5, 6, 15, 16)
    "r": int,       // 起始寄存器地址
    "n": int,       // 读取或写入的数量
    "d": [int]      // 写入的数据数组 (仅在功能码 ≥ 5 时有效)
  },
  "ss": int         // 会话 ID (可选)
}
```

#### 响应报文格式

```json
{
  "i": "string",    // 响应设备的 ShortName
  "ss": "string",   // 会话 ID (与请求一致)
  "d": [int]        // 返回的数据数组 (根据数量 `n` 的值决定长度)
}
```

请求报文由服务器端发送，响应报文由边缘端发送。

### 采集数据

正确安装完 R1000 之后，你就可以在服务器端的 NodeRED 中测试是否可以收到来自边缘端的数据。

你可以通过 Meshtastic 下发 Modbus 命令，来测试是否可以收到来自边缘端的数据。

```json
{
  "i": "0001",
  "t": "r",
  "v": "1",
  "p": "1",
  "c": {
    "a": 1,
    "f": 3,
    "r": 40001,
    "n": 2
  }
}
```

其中 `i` 字段为边缘端的 ShortName，`p` 字段为通道号，`c` 字段为 Modbus 命令对象。

响应值可能为：

```json
{
  "i": "root",
  "ss": "1742891806240",
  "d": [480, 481]
}
```
