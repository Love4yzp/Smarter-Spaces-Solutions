# Home Assistant

Home Assistant 是一个开源的家庭自动化平台，旨在提供本地化控制和统一管理家庭智能设备的能力。本文档概述 Home Assistant，介绍其主要特点、核心概念、安装方式，并指导用户进行初步设置。

>**有没有那么一瞬间，你看着家里五花八门的智能设备——米家的智能灯泡、涂鸦的窗帘电机、Aqara的各种传感器……心里犯嘀咕：为啥它们就不能好好“说话”，一起干点啥惊艳的事情呢？**

>

> **Home Assistant**，这个诞生于2013年的开源项目，如今已成长为GitHub上智能家居领域的绝对明星。它完全免费，可以部署在你自己的设备上（本地化运行），目标只有一个：成为你家庭智能设备的“**中央大脑**”。无论是Wi-Fi、Zigbee、Z-Wave这些通信协议，还是国内外你能想到的各种品牌，HA都能通过 **集成 (Integration)** 这个神奇的功能，把它们拉进一个屋檐下，用一套统一的逻辑去管理、控制和实现自动化。

## 引言

随着物联网（IoT）技术的发展，智能家居设备日益普及。然而，不同品牌和协议的设备通常各自拥有独立的控制应用和云服务，导致设备间互联互通困难，用户操作体验分散，难以实现跨设备的联动和复杂的自动化场景。

Home Assistant 的出现解决了这一核心问题。它作为一个免费且支持在用户本地硬件上运行的平台，能够通过丰富的**集成（Integration）**兼容市场上的众多智能家居设备、协议（如 Wi-Fi、Zigbee、Z-Wave）和在线服务，将它们汇聚到一个统一的管理界面，实现设备的集中控制和自动化协调。

Home Assistant 项目自 2013 年启动以来，已发展成为智能家居领域的领先开源平台之一。其活跃的社区持续贡献新的集成和功能，提供了强大的模块化和可扩展性，使其成为构建可定制化智能家居系统的理想选择。

## Home Assistant 的主要特性

选择 Home Assistant 的主要优势包括：

- **广泛的设备兼容性：** 支持海量智能家居品牌、设备及通信协议，打破品牌间的壁垒。
- **本地化控制与数据隐私：** 平台部署在用户本地网络中运行，数据不强制上传至第三方云端，提高了响应速度，并保护用户隐私。
- **灵活强大的自动化能力：** 提供基于图形界面或 YAML 配置的高级自动化引擎，支持复杂的触发、条件和动作组合，实现精细化的智能场景。
- **开放且活跃的生态系统：** 拥有庞大的社区支持，持续开发新的集成、主题和附加功能（Add-ons），满足多样化需求。
- **可定制的用户界面：** 基于 Lovelace UI，提供灵活的仪表板定制功能，用户可根据偏好组织和展示设备状态及控制界面。

## Home Assistant 的安装方式

Home Assistant 提供了多种安装方法，以适应不同的运行环境和用户管理偏好。这些安装方式随着 Home Assistant 项目的发展和用户需求的变化而逐步形成。

> [!NOTE]
> 最新的官方安装指南请参考：[Home Assistant Installation Methods](https://www.home-assistant.io/installation/#advanced-installation-methods)

下表概述了不同安装方式的核心特点、演进背景及适合用户群体：

| **安装方式**              | **诞生时间**    | **核心特点 / 运行方式**               | **演进背景简述**                     | **适合用户群体**                     |
| :------------------------ | :-------------- | :------------------------------------ | :----------------------------------- | :----------------------------------- |
| Home Assistant Core       | 2013 (项目初始) | Home Assistant 基础，纯 Python 应用   | 项目起点                             | 开发者、对环境有完全控制需求者       |
| Home Assistant Container  | 随后            | 基于 Docker 容器运行 HA Core          | 适应容器化技术发展                   | 熟悉 Docker 的用户                   |
| Home Assistant Supervised | 随后            | 在标准 Linux 上运行 Docker+Supervisor | 整合附加功能，同时保留底层系统控制权 | 需要完整功能且管理底层系统的用户     |
| Home Assistant OS         | 较晚            | 官方集成的定制操作系统，包含 HA+组件  | 简化安装和维护，面向更广泛用户       | **初学者、普通用户、追求稳定便捷者** |

> [!TIP]
> **推荐的安装方式：Home Assistant Operating System (HA OS)**
> 对于大多数首次接触 Home Assistant 的用户，以及希望获得完整功能、图形化管理和便捷维护体验的用户，**强烈推荐选择 Home Assistant Operating System (HA OS)**。该方式提供了预配置好的完整运行环境，安装和后续管理相对简单。

:::details 详细对比

| **安装方式** | **诞生时间** | **背景与核心特点** | **适合人群** | **主要优势** | **需要注意 / 复杂性** | **形象类比** |
| :------------------------ | :----------------------- | :------------------------------------------------------- | :------------------------------------- | :----------------------------------------------- | :------------------------------------------------- | :---------------------- |
| **Home Assistant Core** | **2013年（项目起点）** | 项目最初的形态，纯 Python 应用，只包含最基础的核心和集成能力。 | 开发者、对运行环境有极致控制需求的高级玩家           | 极度灵活、资源占用最少、更新周期自由           | **无图形化管理界面、无加载项商店**、所有依赖和更新需手动维护 | **最原始的DIY工具箱**，所有零件和说明书都在，得自己从零组装 |

| **Home Assistant OS** | **较晚（面向大众化）** | HA 官方推出的**一体化、开箱即用的操作系统**，预装了 HA 及所有附加组件，目标是极致简化安装和维护。曾叫 HassOS。 | **绝大多数初学者、普通用户、追求省心稳定的人** | **最简单、开箱即用、功能最完整（含加载项商店、图形化备份和系统自动更新）** | 底层操作系统相对封闭，不方便安装 HA 以外的其他应用 | **预装了全套智能系统的品牌家电**，买回来插电联网，直接享受服务 |

:::

## 安装 Home Assistant 指南

<Steps>

### 选择你的硬件平台与安装方式

在本入门指引中，我们将以安装 Home Assistant Operating System (HA OS) 为例。你可以选择多种硬件平台来运行 HA OS，例如树莓派、迷你电脑或虚拟机。官方也推出了预装 HA OS 的硬件设备 **Home Assistant Green**。

> [!TIP]
> 基于对初学者的推荐及国内网络环境的考量，推荐选择 **冬瓜 HAOS**。冬瓜 HAOS 是 Home Assistant OS 的一个社区维护分支，针对国内网络环境预置了下载加速源，并可能预装部分常用集成和加载项，能有效简化安装后的配置工作。
> 获取冬瓜 HAOS 镜像请访问：[冬瓜 HAOS](https://www.wghaos.com)。

如果你的硬件平台（如 Home Assistant Green）已经预装了 Home Assistant OS，通常无需自行烧录镜像，可直接跳到“首次访问与基础设置”步骤。如果需要对 Home Assistant Green 进行重置或刷写其他镜像，请参考其官方说明文档：[Resetting the device](https://support.nabucasa.com/hc/en-us/articles/25161225495837-Resetting-the-device)。

### 安装 Home Assistant OS

根据你选择的硬件平台和 HA OS 镜像（如冬瓜 HAOS 或官方镜像），使用 Etcher, balenaSSH 或对应平台推荐的工具将镜像烧录到你的存储介质（SD卡、eMMC、SSD等）上。

烧录完成后，根据你的设备决定是否需要将存储介质插入硬件设备，连接电源和网络（推荐优先使用有线连接），然后启动设备。Home Assistant OS 将自动加载系统，此过程可能需要几分钟。

### 首次访问与基础设置

系统启动完成后，Home Assistant 服务将开始运行。你可以通过以下方式在同一局域网下访问其 Web 用户界面：

1. 在设备浏览器中访问 `http://homeassistant.local:8123`。
2. 如果 `.local` 地址无法解析，请尝试查找 Home Assistant 设备在路由器中获得的 IP 地址，并通过 `http://[HA设备的IP地址]:8123` 访问。
3. 使用 Home Assistant Companion 手机应用（iOS/Android），应用通常能自动发现本地网络中的 HA 实例并提供快捷访问。

首次访问 Home Assistant 界面时，系统会引导你完成以下初始化设置：

1. **创建本地管理员账户：** 设置用户名和密码，用于后续登录和管理 Home Assistant。请妥善保管此账户信息。
2. **设置家庭信息：** 输入家庭名称、精确的位置信息（用于地理位置相关的自动化、区域管理及天气等信息显示）、单位制等。
3. （可选）自动发现：Home Assistant 可能会自动检测到局域网内部分易于发现的设备或服务，并提示你添加对应的集成。

### 添加设备与配置仪表板

完成基础设置并进入 Home Assistant 主界面后，下一步是将你的智能家居设备接入平台。

#### 添加你的智能设备

Home Assistant 通过安装**集成**来连接和管理不同品牌和协议的设备及服务。

1. 在 Home Assistant 用户界面左侧导航栏，点击 **“设置”**。
2. 进入 **“设备与服务”**。
3. 点击右下角的 **“+ 添加集成”** 按钮。
4. 在搜索框中输入设备品牌、服务名称或协议（例如：`Xiaomi`、`Tuya`、`Philips Hue`、`MQTT`、`Zigbee`）来查找并选择对应的集成。
5. 按照界面提示完成集成配置流程。不同集成所需的配置信息不同，可能包括网络扫描、输入账户凭据、设备 IP、API Key 或物理配对（如 Zigbee/Z-Wave 设备需要通过协调器进行配对）等步骤。

配置成功后，该集成将扫描并向 Home Assistant 添加其支持的**设备**和相应的**实体**。你可以在“设备与服务”页面查看到已添加的设备和实体列表。

:::tip 添加小米米家设备示例

小米设备在国内用户中普及率高。除了官方提供的[小米集成](https://github.com/XiaoMi/ha_xiaomi_home)，社区维护的[小米 Miot 集成](https://github.com/al-one/hass-xiaomi-miot)通常支持更多设备类型和功能。可以在 Hassbian 论坛或通过 HACS (Home Assistant Community Store，一个社区维护的第三方集成商店，通常在冬瓜 HAOS 中易于安装或已预装) 查找和安装小米 Miot 集成。配置时可能需要获取小米设备的 Token 或在米家 App 中进行特定设置，具体请参考对应集成的文档。

:::

### 将设备/实体添加到概览界面（仪表板）

即使设备和实体已经被 Home Assistant 发现，它们并不会自动以直观的方式显示在主界面的 **概览（Overview）** 页面上。你需要手动或通过特定的配置，将这些实体添加到仪表板的 **卡片（Card）** 上，才能方便地查看状态和进行控制。

1. 访问 Home Assistant 主界面（概览页面）。
2. 点击右上角的**三个点菜单**。
3. 选择 **“编辑仪表板”**，（*首次访问时，如果概览是空的，界面可能会直接提示你添加卡片*）
4. 点击右下角的 **“+ 添加卡片”** 按钮。
5. 在弹出的卡片类型列表中，选择适合你要添加的实体的卡片类型。
    - **“实体”卡片 (Entities Card)：** 最常用，可以将多个不同类型的实体列表显示在一起。
    - **“灯”卡片 (Light Card)：** 专门用于控制灯光实体，提供亮度、颜色控制界面。
    - **“传感器”卡片 (Sensor Card)：** 用于显示传感器实体的历史图表或当前状态。
    - 还有其他多种卡片类型（如开关、媒体播放器、天气、图表等）。
6. 选择卡片类型后，在配置界面选择或输入你要关联的**实体**。根据卡片类型，可能还需要配置标题、图标等。
7. 点击 **“保存”** 将卡片添加到仪表板。
8. 重复步骤 4-7 添加更多卡片，将你关心的设备和实体添加到仪表板的不同视图（View）中，或者拖动卡片调整布局。
9. 编辑完成后，点击左上角的 **“完成编辑”**。

现在，你添加到卡片上的设备实体就可以直接在概览界面上查看状态和进行控制了！这是 Home Assistant 日常使用的核心交互方式。

</Steps>

## Home Assistant 核心概念

理解 Home Assistant 的核心概念，就像学习任何新系统一样，掌握其基础构成元素至关重要。例如，在使用电脑时需要了解文件、文件夹的概念。Home Assistant 也有几个核心的抽象层，理解它们能帮助你更高效地管理设备和配置自动化。

有关这些概念的更详细说明，请参考官方文档：[Concepts and terminology - Home Assistant](https://www.home-assistant.io/getting-started/concepts-terminology/)。

### 1. 集成 (Integration)

**集成**是 Home Assistant 与外部服务、设备、平台或技术连接的接口。通过安装和配置集成，Home Assistant 能够“认识”并与之通信，从而发现和控制特定品牌的设备，或者获取天气、日历等外部信息。Home Assistant 内置了数千种集成，社区也贡献了大量第三方集成。

- 示例：Tuya 集成、Aqara 集成、Philips Hue 集成、MQTT 集成、天气预报集成等。
- 操作：在“设置 → 设备与服务 → 添加集成”中搜索并安装。

### 2. 设备 (Device)

在 Home Assistant 中，一个**设备**通常代表一个物理智能硬件产品，例如一个智能灯泡、一个温湿度传感器、一个智能插座、一台空调主机或一个网关。设备是逻辑上的分组，它包含了该硬件提供的所有功能和状态。

- 示例：一个名为“客厅主灯”的飞利浦 Hue 灯泡，一个米家的温湿度传感器。
- 层级关系：一个设备可以包含一个或多个实体。

### 3. 实体 (Entity)

**实体**是 Home Assistant 中可被独立控制、监测或操作的最小逻辑单元。如果说“设备”是一个物理对象，那么“实体”就是这个设备暴露出来的具体功能点或数据点。自动化和用户界面的操作最终都是针对实体进行的。每个实体都有一个唯一的 `entity_id`（格式通常为 `domain.object_id`）。

- 常见的实体类型（由其所属的“领域”domain 决定）：
  - `light` (灯)：控制灯的开关、亮度、颜色等。
  - `switch` (开关)：控制开关类设备的状态。
  - `sensor` (传感器)：报告数值或状态（如温度、湿度、电量、门窗是否打开）。
  - `binary_sensor` (二元传感器)：特殊的传感器，只有两种状态（如开/关，移动/静止）。
  - `media_player` (媒体播放器)：控制音箱、电视等播放设备。
  - `lock` (锁)：控制智能门锁的锁定/解锁状态。
- 示例：
  - “客厅主灯”设备下的 `light.keting_zhudeng` 实体（控制开关/亮度/颜色）。
  - “米家温湿度传感器”设备下的 `sensor.wendusensor_temperature` 实体（报告温度数值），`sensor.wendusensor_humidity` 实体（报告湿度数值）。

---

> [!INFO]
> 要让 Home Assistant 识别和管理你的**设备**，首先需要安装并配置对应的**集成**。每个**设备**则会向 Home Assistant 暴露出一个或多个**实体**。你的自动化规则和用户界面操作，最终都是通过控制、读取或监听这些**实体**的状态来实现的。
>
> 理解这种层级关系是使用 Home Assistant 的基础。

### 4. 组织设备与实体

为了便于管理大量的设备和实体，Home Assistant 提供了组织工具：

- **区域 (Area)：** 将设备和实体按物理空间分组，例如“客厅”、“卧室”。区域有助于批量控制设备和设置基于位置的自动化。
- **楼层 (Floor)：** 在房屋有多层时，用于在区域之上进行更高层级的划分。
- **标签 (Label)：** 自定义的分类标记，可应用于设备、实体等，用于快速查找、过滤或在特定配置中使用。

### 5. 加载项 (Add-ons)

加载项是 Home Assistant OS 和 Supervised 版本特有的功能，它们是运行在 Home Assistant 环境中，为平台提供附加服务或工具的应用程序。加载项通过 Supervisor 进行管理。

常见的加载项包括：

- **Advanced SSH & Web Terminal** 对于 OS，利用此插件可以方便的进行终端交互，访问 Editor 无法进行的层面；  
- **File Editor** 则给初学者带来最直观的配置文件编辑体验，主要用于基本的配置文件的 YAML 配置文件编辑。

- **Node-RED：** 一个流程化的编程工具，提供图形界面通过连接节点来构建复杂的自动化逻辑。

- **ESPHome：** 帮助开发者通过简单的 YAML 配置而非编写代码来创建自定义的 ESP 系列芯片设备固件，并集成到 HA。

- **Mosquitto broker：** 一个轻量级的 MQTT 消息代理，用于接收和分发 MQTT 消息，常用于 DIY 设备或解耦通信。
- **EMQX** Mosquitto 的替代，便于更加清晰的管理；  

加载项极大地扩展了 Home Assistant 的功能边界。

### 6. 自动化、场景与脚本

这三者是 Home Assistant 实现智能家居联动的[核心组件](https://www.home-assistant.io/docs/automation)。

- **自动化 (Automation)：** 定义了 Home Assistant 根据特定事件自动执行操作的规则。一个自动化由一个或多个**触发器 (Triggers)**、可选的**条件 (Conditions)** 和一个或多个**动作 (Actions)** 组成。
  - **触发器：** 启动自动化的事件（如设备状态变化、时间到达、传感器阈值）。
  - **条件：** 自动化执行动作前必须满足的附加判定（如特定时间段、设备处于特定状态、用户在家）。
  - **动作：** 自动化被触发且条件满足后要执行的操作（如打开灯、发送通知、运行脚本、切换场景）。
- **场景 (Scene)：** 记录一组设备在特定状态下的“快照”。激活一个场景会立即将所有包含的设备设置为该场景定义的状态。场景本身不包含自动化逻辑，常被用于自动化或脚本的动作中，实现一键切换多种设备状态。
- **脚本 (Script)：** 一系列按顺序执行的动作序列。脚本可以被手动调用执行，也可以在自动化或场景中作为动作来运行。脚本可包含延迟、条件判断（有限）等步骤，用于封装一组可复用的操作流程。与自动化不同，脚本没有内置的触发器，它是一个被动的执行者。

自动化、场景和脚本相互配合，能够构建高度个性化和智能化的家居控制逻辑。

- **触发器（Triggers）：** 事件（开关变化、时间调度、传感器数值超限等）  
- **条件（Conditions）：** 对触发条件作出进一步判断（如“只在晚上进行”或“只有在温度高于 30℃ 时执行”）  
- **动作（Actions）：** 要让系统执行的操作，比如“打开灯”、“发送通知”、“切换场景”等。

- 一次性设置多个设备的目标状态，比如“回家场景”中灯光亮度、窗帘打开程度、音响音量等，全部只需一键切换。
